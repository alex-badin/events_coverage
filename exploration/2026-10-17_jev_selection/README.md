# Jev вместо rerank Cohere: как отбирать посты о событии (17.10.2026)

Вопрос: как использовать модель решений TypeSafe Jev 1.13 (через OpenRouter) на шаге после поиска по
сходству, чтобы отобрать посты о событии ФОМ, и как выбирать, где резать список, если один общий
порог ненадёжен.

## Коротко

Термины. ФОМ — Фонд «Общественное мнение»; его еженедельный опрос даёт события недели (название и
цитаты респондентов). W08–W11 — ISO-недели 2025 года. Jev 1.13 — модель TypeSafe, которая не пишет
текст, а отвечает на типизированные вопросы; вопрос `noul` — да/нет, ответ — вероятность «да».
Codex — CLI OpenAI, здесь с моделью gpt-6.1-sol, по подписке. Проба — один поисковый запрос: название
события или одна цитата респондента; у события 4–9 проб.

**Механизм** (на событие):
1. Поиск по сходству полного текста даёт кандидатов (здесь 3 000).
2. Один вызов модели пишет **описание события**: что произошло, что ещё считается освещением
   (реакции, последствия, подготовка), что не считается (похожие события той же темы). Модель видит
   название ФОМ, слова респондентов и 40 ближайших постов. Здесь писала gpt-6.1-sol через Codex.
3. Jev отвечает по каждому кандидату на вопрос да/нет (`noul`) «сообщает ли пост об этом событии»,
   описание события — в вопросе. Ответ — вероятность «да».
4. **Порог — свой для каждого события.** LLM читает 100 постов, взятых поровну из десяти полос
   вероятности Jev равной ширины (читатель — DeepSeek V4 Flash, около $0.001 на событие; с ним F1 в пределах 0.01 от
   F1 с метками Codex на 7 событиях из 8, см. «Кто читает выборку»), и порог ставится там, где F1 на этой
   выборке лучше всего.

**Почему так:**
- Описание события — главный выигрыш. Без него Jev понимал название события буквально и отсекал
  посты о подготовке, реакциях и последствиях; с ним AUC на пяти размеченных событиях 0.96–0.99
  вместо 0.89–0.99, F1 на «Росте цен» при общем пороге 0.84 вместо 0.66.
- Один общий порог не переносится на новые события: порог, подобранный на пяти размеченных, на трёх
  новых даёт F1 на 0.04–0.08 ниже лучшего возможного. Порог по выборке из 100 постов — в пределах 0.01
  от лучшего возможного на всех трёх.
- На двух новых событиях из трёх Jev с порогом по выборке намного лучше Cohere с действующим порогом
  0.35 (порог на балл релевантности Cohere): F1 0.91 против 0.74 (атака дронов на Москву) и 0.82
  против 0.68 (встреча Путина и Лукашенко). На третьем («Высказывания и действия Трампа») Cohere при
  0.35 даёт 0.60, а с порогом по выборке догоняет Jev: 0.89 против 0.90.
- Cohere не спасает и свой лучший возможный порог: на дронах и Лукашенко его F1 не выше 0.74 и 0.71.
  Порог по выборке помогает Cohere только на событии о Трампе.

## Данные и как мерили

**Пять размеченных событий** (W08–W11 2025, из `../2026-10-17_fulltext_vs_summary/`): 772–809 постов на
событие, метки gpt-6.1-sol через Codex по полному тексту. Эти посты — объединение двух первых пятисот
по сходству и выборок до 3 000-го места, поэтому постов о событии среди них больше, чем в реальном
списке кандидатов. На этих событиях выбирались формулировка вопроса и общий порог.

**Три новых события** из того же окна с полным текстом, на них ничего не подбиралось:
- «Обстрелы российских территорий, атака беспилотников на Москву», W11;
- «Встреча В. Путина и А. Лукашенко», W11;
- «Высказывания и действия Д. Трампа», W10.

На каждое — 3 000 кандидатов по сходству полного текста (как в `run.py score`). Jev и Cohere
(`rerank-v3.5`, полный текст, по запросу на каждую пробу, лучший балл) оценили все 3 000. Эталон: Codex
разметил 750 постов на событие, по 150 случайных из пяти полос места по сходству (1–150, 151–500,
501–1 000, 1 001–2 000, 2 001–3 000), тем же промптом, что и пять событий, без описания события. Выборка
не зависит ни от Jev, ни от Cohere; каждый размеченный пост пересчитан с весом на свою полосу, так что
все числа ниже — оценки на все 3 000 кандидатов.

**Формулировки вопроса к Jev** (все в одном запросе на пост, `common.question`):
- v0 — да/нет, название события и слова респондентов (первый тест);
- v1 — выбор из четырёх градаций (само событие / реакция или последствие / та же тема, другое событие /
  не о том); «о событии» = сумма вероятностей первых двух;
- v2 — v1 плюс описание события;
- v3 — да/нет плюс описание события.

**Правила отсечения:**
- лучший возможный — порог с лучшим F1 по всем меткам события (верхняя граница, на деле недоступен);
- общий — один порог с лучшим F1 на других событиях (на размеченных — по остальным четырём, на новых —
  по всем пяти размеченным);
- по выборке — 100 постов из десяти равных полос оценки, порог с лучшим F1 на них; 200 повторов,
  среднее. В симуляции метки выборки — те же метки Codex.

F1 — среднее гармоническое точности и полноты отобранного списка. «Потеряно» — посты о событии ниже
порога; «лишних» — посты не о событии выше порога.

## Кто читает выборку: дешёвая модель вместо Codex

В симуляции выше 100 постов для порога «читал» Codex (gpt-6.1-sol, по подписке). В работе их будет
читать модель по API. Две дешёвые модели через OpenRouter разметили те же посты, из которых
симуляция тянет выборки: все 6 222 поста с метками Codex на восьми событиях (793–809 на
размеченных, по 750 на новых), тем же промптом `run.PROMPT` (название, слова респондентов, окно, без
описания события), по 50 постов в запросе. Затем те же 200 выборок по 100 постов из десяти полос
вероятности Jev v3: порог ставится по меткам читателя, а F1, «потеряно» и «лишних» считаются по
меткам Codex, как раньше (на новых событиях — оценки на 3 000 кандидатов).

(рассуждение выключено). Средние по 200 выборкам; «потеряно» и «лишних» — в постах. Совпадение — доля
постов события, где метка модели равна метке Codex (без весов полос).

- **Рекомендуемый читатель — DeepSeek V4 Flash.** На семи событиях из восьми его F1 в пределах 0.01 от
  F1 с метками Codex, на всех трёх новых — 0.898–0.911 против 0.897–0.913. Хуже всего на встрече Трампа
  и Зеленского: 0.934 против 0.956, он строже Codex (564 поста о событии против 637), порог встаёт
  выше и теряет 70 постов вместо 20.
- Qwen на размеченных событиях наравне с Codex, но на двух новых из трёх хуже: на Лукашенко F1 0.779
  против 0.820 и вдвое больше лишних (122 против 58), на дронах 196 лишних против 103. На новых
  событиях постов не о событии больше, и Qwen там щедрее Codex с «да». Худшие 10% выборок у него тоже
  заметно ниже (Лукашенко 0.72, у Codex и DeepSeek 0.82).
- Стоимость чтения 100 постов (два запроса): DeepSeek около $0.001 на событие, Qwen около $0.004 — по
  фактическому расходу этого прогона. Это меньше прежней оценки в $0.30 для gpt-6.1-sol: посты в
  среднем короче 2 500 знаков (~650 знаков, ~11 тыс. входных токенов на 50 постов).
- Надёжность: DeepSeek ответил на все 126 запросов. У Qwen два запроса из 126 (93 поста «Переговоров
  Путина и Трампа») при каждом повторе давали битый JSON; для них в симуляции оставлены метки Codex.
  Qwen с рассуждением (по умолчанию или `effort: low`) тратил 20–24 тыс. токенов на запрос (~$0.01),
  поэтому шёл без рассуждения. `openai/gpt-6-luna` планировался вторым, но OpenRouter отказывает этому
  аккаунту во всех моделях OpenAI (403 «violation of provider Terms Of Service», даже на «Say ok»).
- Расход этого шага: $0.38 по журналу `spend.jsonl` (Qwen $0.28, DeepSeek $0.10, в том числе
  $0.042 — верхняя оценка за прогон DeepSeek, который упал до записи расхода). Всего по журналу $3.57.

## Стоимость

Этот эксперимент: $3.20 по журналу `data/interim/jev_selection/spend.jsonl` (Jev $1.88, Cohere $1.32,
векторы запросов — доли цента), плюс $0.18 первого теста Jev. Описания событий и вся разметка —
подписка Codex, без оплаты API.

На одно событие в работе (оценка, не замер):
- Jev v3 на 3 000 кандидатов: пост ~1 000 токенов плюс вопрос с описанием ~1 000, ~6M токенов по
  $0.042 за 1M — около $0.25. Cohere на тех же 3 000 стоил $0.26–0.59 (зависит от числа проб).
- Чтение 100 постов для порога: DeepSeek V4 Flash — около $0.001 (замер, раздел выше).
- Описание события: один вызов, центы.
- Сейчас конвейер передаёт в rerank всех кандидатов с косинусным сходством выше 0.30, до 27 582 на
  событие. На таком
  списке Jev v3 — около $2 на событие, Cohere при 7 пробах — около $3.5.

## Ограничения

- Эталон — одна модель (gpt-6.1-sol), не люди. Описания событий писала та же модель; размечала она без
  описания, но своё понимание границ события у неё одно, поэтому согласие Jev с описанием и Codex может
  быть завышено.
- Читатель выборки проверен по меткам Codex, а не людей: DeepSeek совпадает с Codex на 79–95% постов,
  и F1 считается по тем же меткам Codex.
- Восемь событий одного окна (февраль–март 2025), где есть полный текст. Полнота за пределами 3 000
  кандидатов по сходству не измерялась ни для одного способа.
- Выборка для порога брала посты из полос оценки равными долями; другие схемы (по месту в списке, с
  остановкой по пачкам, как в misinfo_tracking_moldova) не сравнивались.

## Файлы

- `common.py` — события, кандидаты, формулировки вопроса к Jev (бесплатно).
- `calls.py` — платные шаги `cosine`, `jev`, `cohere`; общий журнал расходов, остановка на $4.50.
- `briefs.py` + `codex_answer.sh` — описания событий через Codex.
- `holdout_labels.py` + `codex_answer.sh` — эталонная разметка новых событий.
- `reader_prompts.py` (бесплатно) + `reader_calls.py run|collect` (платно) — разметка выборки
  дешёвыми моделями через OpenRouter; метки в `data/interim/jev_selection/reader_labels/`.
- `evaluate.py dev|holdout|readers` — AUC, правила отсечения и порог по меткам разных читателей; результаты в
  `data/interim/jev_selection/evaluation_*.json`.
- `data/interim/jev_selection/` (не в git) — описания, ответы Jev и Cohere, метки, журнал расходов.
