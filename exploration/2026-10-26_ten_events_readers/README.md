# Jev на десяти контрольных событиях и три модели-читателя (26.10.2026)

Вопрос: держится ли отбор постов о событии через Jev (метод из `../2026-10-17_jev_selection/`) на
десяти контрольных событиях вместо трёх, в том числе на событиях 2020–2022 годов, и какая модель
должна читать выборку из 100 постов, по которой ставится порог: DeepSeek V4 Flash, Claude Haiku 5.5
или Claude Sonnet 5.5.

## Коротко

Термины. ФОМ — Фонд «Общественное мнение», его еженедельный опрос даёт события недели. Кандидаты —
3 000 постов окна, ближайших к событию по сходству векторов полного текста. Jev 1.13 — модель
TypeSafe, которая на вопрос да/нет отвечает вероятностью «да»; здесь формулировка v3 из теста 17.10:
«сообщает ли пост об этом событии» плюс короткое описание события (что было, что считается и что не
считается освещением), которое заранее пишет gpt-6.1-sol. Описание видит только Jev; читатели и
эталон судят по названию события ФОМ и словам респондентов. **Читатель** — модель, которая размечает
100 постов, взятых поровну из десяти полос вероятности Jev; порог ставится там, где F1 на этих 100
постах лучше всего («порог по выборке»). «Лучший возможный» порог — лучший по всем меткам события
(на деле недоступен); «общий» — один порог 0.20 на все события. Эталон — разметка Codex (gpt-6.1-sol)
750 постов на событие, как в прошлых тестах. F1 — среднее гармоническое точности и полноты.
«Потеряно» и «лишних» — оценки в постах из 3 000 кандидатов; «из 750» — без пересчёта, по
размеченным постам.

- **Рекомендуемый читатель — DeepSeek V4 Flash.** На всех десяти событиях его F1 в пределах 0.006
  от F1 с порогом по меткам Codex (0.820–0.997 против 0.820–0.999). Около $0.015 на событие (два
  запроса по 50 постов).
- **Haiku и Sonnet проваливаются на событиях с размытыми границами.** Haiku на атаке беспилотников на
  Москву: F1 0.638 вместо 0.913 (говорит «да» на 589 постов из 750, Codex — на 347), на Карабахе
  0.893 вместо 0.945. Sonnet на «Высказываниях и действиях Трампа»: 0.531 вместо 0.897 (говорит «да»
  на 258 постов из 750, Codex — на 635), на встрече Путина и Лукашенко 0.708 вместо 0.820; Haiku там
  же 0.795. На остальных шести событиях оба в пределах 0.01 от Codex.
- **На событиях 2020–2022 годов метод держится.** AUC Jev 0.94–0.99; F1 с порогом по выборке
  (метки Codex) 0.87–0.99 и не ниже лучшего возможного больше чем на 0.01. Промпт разметки на
  постах 2020–2022 работает так же, как на 2025 годе (проверено вручную на первой порции каждого
  события до запуска остальных).
- **Но эта проверка слабее, чем выглядит.** У шести из семи новых событий Codex считает о событии
  79–99.6% из 3 000 кандидатов (оценка): постов о них в окне больше, чем 3 000. Отделять там почти
  нечего: F1 0.95–1.00 при любом пороге, в том числе при общем 0.20. Различает правила только
  отставка правительства в 2020-W03 (о событии около 1 641 из 3 000): там порог по выборке даёт 0.87
  при лучшем возможном 0.88, общий порог — 0.82. Для крупных событий узкое место — 3 000 кандидатов,
  а не порог (см. `../2026-10-18_candidate_depth/`).
- **Расход: $5.37 из бюджета $10, который Алекс одобрил на эту задачу** (Jev $1.69, Sonnet $2.17, DeepSeek $0.78, эмбеддинги $0.43,
  Haiku $0.30). Описания событий и эталонная разметка — подписка Codex.

## Как мерили

На каждое новое событие то же, что в `../2026-10-17_jev_selection/` для трёх прошлых:
1. **Посты окна** (неделя −3/+10 дней): `original_message`, JSON военных каналов развёрнут, у каждого
   канала срезаны повторяющиеся концовки, убраны ссылки, @-имена, `#` и эмодзи (как в
   `../2026-10-17_fulltext_vs_summary/`). От 12 506 постов с текстом (2020-W03) до 69 991 (2022-W07).
   В окнах 2020–2021 годов концовок почти нет (3–4 на окно против 57–86 в 2022–2024).
2. **Векторы** Qwen3-Embedding-8B (OpenRouter) для фрагментов 650 символов с перекрытием 120;
   362 тыс. фрагментов. Проба — один поисковый запрос (название события, одна цитата респондента или
   их склейка, 6–12 на событие); балл поста — лучший фрагмент по лучшей пробе.
3. **3 000 кандидатов** по этому сходству.
4. **Описание события** — gpt-6.1-sol через Codex, тот же промпт (`briefs.PROMPT`).
5. **Jev v3** на всех 3 000 — тот же вопрос, собран тем же кодом (`common.question`).
6. **Эталон** — Codex, 750 постов на событие: по 150 случайных из пяти полос по месту в списке кандидатов (1–150, 151–500,
   501–1 000, 1 001–2 000, 2 001–3 000), тот же промпт `run.PROMPT` (название, слова респондентов,
   окно, без описания события). Каждый пост пересчитан с весом на свою полосу, поэтому числа ниже —
   оценки на все 3 000 кандидатов.
7. **Читатели** размечают те же 750 постов тем же промптом `run.PROMPT`, по 50 постов в запросе:
   - DeepSeek — `deepseek/deepseek-v4-flash` через OpenRouter, рассуждение по умолчанию; для трёх
     прошлых событий взяты его метки от 17.10;
   - Haiku — `claude-haiku-5-5`, Anthropic API, усилие `low`, ответ по JSON-схеме;
   - Sonnet — `claude-sonnet-5-5`, так же, через Message Batches API (вдвое дешевле).

   Для трёх прошлых событий промпты читателей побайтно совпадают с промптами теста от 17.10.

Правила отсечения (все по Jev v3):
- **лучший возможный** — порог с лучшим F1 по всем меткам события (верхняя граница, на деле недоступен);
- **общий** — один порог 0.20, подобранный на пяти размеченных событиях теста 17.10;
- **по выборке** — 100 постов поровну из десяти равных полос вероятности Jev, порог с лучшим F1 на
  них; 200 повторов, среднее. Порог ставится по меткам читателя, а F1, «потеряно» и «лишних»
  считаются по меткам Codex.

«Потеряно» — посты о событии ниже порога; «лишних» — посты не о событии выше порога; оба — в постах
из 3 000 кандидатов. «Совпадение» — доля из 750 постов события, где метка читателя равна метке Codex
(без весов полос).

## Ограничения

- Эталон — одна модель (gpt-6.1-sol через Codex), не люди. Где Haiku или Sonnet расходятся с
  Codex о границе события, неизвестно, кто ближе к тому, что имели в виду респонденты; рекомендация
  DeepSeek значит «ставит порог так же, как ставил бы Codex».
- Шесть из семи новых событий крупные: среди их 3 000 кандидатов о событии 79–99.6%. На них
  нельзя проверить, хорошо ли метод отсекает лишнее; это проверено на четырёх событиях из десяти
  (отставка правительства, дроны, Лукашенко и отчасти Трамп). Для таких событий 3 000 кандидатов
  мало, и полнота за 3 000-м местом не измерялась.
- Читатели сравнивались без описания события в промпте (как в тесте 17.10). С описанием спор о
  границах у Haiku и Sonnet, вероятно, уменьшился бы; это не проверялось.
- Каждый читатель — один прогон; повторный прогон тех же моделей может дать немного другие метки.
